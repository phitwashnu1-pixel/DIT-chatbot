=========================================================
แผนผังการทำงานของระบบ (System Flow) - DIT ChatBot
=========================================================

เอกสารนี้อธิบายขั้นตอนการทำงานตั้งแต่ผู้ใช้พิมพ์คำถาม จนกระทั่งระบบประมวลผลและตอบกลับ เพื่อให้เห็นภาพรวมของระบบทั้งหมด (Architecture & Logic Flow)

---------------------------------------------------------
อธิบายขั้นตอนการทำงาน (Step-by-Step)
---------------------------------------------------------

ขั้นที่ 1: ฝั่งผู้ใช้งาน (Frontend)
1. ผู้ใช้ (นักเรียน/ครู) พิมพ์คำถามผ่านหน้าเว็บ แชทบอทบนมือถือหรือคอมพิวเตอร์
2. ระบบ Frontend จะส่งคำถามนั้นไปยังเซิร์ฟเวอร์หลังบ้านผ่าน API Endpoint (/api/chat)

ขั้นที่ 2: การประมวลผลคำถาม (Backend - Data Processing)
3. Normalize Query: ระบบจะนำคำถามมาลบช่องว่างทิ้ง ตัดคำว่า "ปวช" ออก และแปลงเครื่องหมาย / ให้เป็น - เพื่อป้องกันปัญหาการค้นหาไฟล์ผิดพลาด (เช่น พิมพ์ "ปวช 3/2" จะถูกแปลงเป็น "3-2")
4. Synonym Dictionary: ระบบจะจับคู่คำเรียกสาขาให้ตรงกับชื่อไฟล์ เช่น 
   - "ธุรกิจดิจิทัล" จะถูกแปลงเป็น "ธดท"
   - "ไอที" หรือ "เทคโนโลยีสารสนเทศ" จะแปลงเป็น "it" หรือ "เว็บ"
   - "เกม", "แอนิเมชัน" จะแปลงเป็น "เกม"
5. RAG (Retrieval-Augmented Generation): ระบบจะนำคำที่แปลงแล้วไปค้นหา (Search) ในไฟล์ฐานข้อมูล src/data.json ว่ามีชื่อห้อง ชื่อครู หรือรหัสชั้นเรียนตรงกับคำถามหรือไม่
6. Decision (การตัดสินใจ):
   - ถ้าเจอ: ระบบจะตัดเอามาเฉพาะข้อมูล JSON ของตารางนั้นๆ (ขนาดเล็กมาก) ส่งให้ AI
   - ถ้าไม่เจอ: ระบบจะไม่ส่งข้อมูลใดๆ (ส่งค่าเป็น null) เพื่อประหยัดเวลาและป้องกัน AI นั่งอ่านฐานข้อมูลทั้งหมด

ขั้นที่ 3: การประกอบคำสั่ง (Prompt Engineering)
7. ระบบจะคำนวณวันและเวลาปัจจุบัน (Timezone ไทย) ใส่เข้าไปในคำสั่งเบื้องหลัง
8. สร้าง System Prompt เพื่อบังคับพฤติกรรมบอท เช่น:
   - บังคับให้เป็น "ผู้ชาย" (ใช้คำว่า ครับ/ผม)
   - บังคับให้แสดงผลเป็นตาราง Markdown
   - บังคับให้ถามสาขา (เทคโนโลยีสารสนเทศ/ธุรกิจดิจิทัล/เกมและแอนิเมชัน) หากไม่มีข้อมูล (null)
   - บังคับให้ตอบสั้นกระชับ ไม่เยิ่นเย้อเพื่อประหยัด Token

ขั้นที่ 4: การเรียกใช้ AI และความปลอดภัย (Security & API Key)
9. API Key Rotation: ระบบจะสุ่มเลือก Google Gemini API Key จากคลังที่เตรียมไว้ เพื่อกระจายโหลดการทำงาน ป้องกันปัญหา API ติดลิมิต (Rate Limit)
10. หากส่งไปแล้ว Key แรกพัง ระบบจะลอง Key ถัดไปทันที (Retry Logic) หากพังหมด จะส่ง Error แจ้งเตือนไปที่หน้าจออย่างสุภาพ

ขั้นที่ 5: AI ประมวลผลและส่งกลับ (AI & Streaming)
11. Google Gemini ประมวลผลและทำการ Stream (พิมพ์ทีละตัวอักษร) ส่งข้อมูลกลับมาที่ Backend ทันที
12. เมื่อตอบเสร็จสมบูรณ์ ระบบหลังบ้านจะนำจำนวน Token ที่ใช้ไป (Prompt, Completion, Total) ไปบันทึกลง Vercel Logs เพื่อให้นักพัฒนาตรวจสอบการใช้งานได้
13. ข้อมูลถูกส่งไปถึงหน้าจอ Frontend และถูกแปลงเป็นตารางที่สวยงาม พร้อมรองรับการเลื่อนดูข้อมูลบนหน้าจอมือถือ
